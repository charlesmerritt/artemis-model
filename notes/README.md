- [Terminology](terminology.md) — **read first for vocabulary.** Distinguishes the three concepts that get conflated: **FIA plot** (inventory sample, one imputed per pixel, 693 unique in the pilot), **management unit** (delineated decision polygon, our modeling "stand", thousands per county), and **FVS stand** (simulation unit — = plot in the baseline, = management unit in the target). Plus area-weighting rules and the "693 is plots, not stands" convention.
- [Claude Code cloud environment](claude-code-web-environment.md) — why the environment setup script does what it does: which hosts the egress policy denies (`rclone.org`, `astral.sh`, the PPAs, and `extensions.duckdb.org`, the last of which costs 9 tests and needs an admin), the rclone `AWS_CA_BUNDLE` shim without which every S3 call fails, and the three-file split between machine setup, repo bootstrap, and the Dockerfile.

- [FVS restart fidelity findings](restart-fidelity-findings.md) — **measured**: in-process pause reproduces a continuous run exactly (0.0 delta incl. carbon), but `--restart` silently collapses `Forest_Shrub_Herb` to 0.02 and understates total stand carbon ~8% per barrier while BA/Tpa/SDI stay bit-identical. `putstd` omits the FFE commons; `COVTYP` is the likely culprit. Also: a negative FVS restart code is a *signal* — `fvsRun()` must be called again or the store file is empty.

- [Management unit pilot workflow](management_units.md) — decisions, inputs, missing data, and first-notebook scope for Florida timber management units. **Updated 2026-08-03**: BMP buffers are retained as grow-only `riparian` units instead of erased, with a per-county `area_accounting.csv` enforcing `Σ managed + Σ riparian == (forest ∩ parcels) − (waterbodies ∪ road buffer)`. Documents four pre-existing defects the accounting check exposed — CRS-less read masks emptying every clipped layer, a stale LANDFIRE value range emptying the forest mask, `buffer(0)` deleting valid clockwise-wound polygons, and a county-scale `union_all()` segfaulting GEOS — plus the `sliver_merge.py` gap that will dissolve riparian identity if run as-is.

- [Identifier precision](identifier-precision.md) — **every join in ARTEMIS runs on a FIA control number, and a float silently breaks it.** Audit of `PLT_CN`/`TM_ID`/`STAND_CN` handling across the R scripts, pipeline, notebooks, and DuckDB cells. The widest leak was `r/02` casting `PLOT.CN` through `as.numeric()` before writing the TM_ID→PLT_CN crosswalk the whole pipeline joins on. Rules now enforced by `pipeline/ids.py`; **open: pre-existing `/mnt/d` outputs are unaudited and may carry damaged control numbers.**

- [Ownership bundling: pixel-share vs. dominant-owner threshold](ownership-bundling-pixel-share.md) — **measured**: the orchestrator sketch's ">70% of a stand's pixels" rule keeps only 212/693 stands and 23% of AOI acres, because a TreeMap stand is an imputed FIA plot scattered across owners, not a spatially coherent unit. Pixel-share allocation keeps the whole AOI and is sound for supply-side accounting; harvest *application* needs real management units. Includes the denominator trap (full footprint vs owner-classified pixels only: 212 vs 364 stands).
- [How TreeMap works](treemap-methodology.md) — TreeMap = imputed FIA plot-ID raster (modified Random Forest, one plot per pixel); stores per-acre densities not per-pixel totals; `Count` field enables area expansion; pixel sums ≠ FIA design-based estimates. Grounds the per-acre vs area-weighting question.
- [FIA vs TreeMap per-forest-type validation](fia-treemap-fortype-validation.md) — **measured 2026-08-03**: mean-balancing to FIA area per FORTYPCD fixes the area term (−4.7% → −0.4% acres) but leaves attribute bias and makes BAA/carbon slightly *worse* (−6.9% → −7.4%, −13.8% → −15.5%). Gross per-type area misallocation is 21.3% of FL forest area behind a 4.7% net error; Nonstocked is 99.9% absent from the raster; median type ESS is 3 plots. Also documents the 5 defects that kept `r/07_FL_FIA_TreeMap_comparison.R` from ever running.
