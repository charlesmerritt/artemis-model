A shared minimum age at treatment time

The owner-prescription resolver and comparison-scenario renderer now use one harvest_eligibility policy from management_regimes.yaml. Fifteen years is a conservative project assumption for all managed entries; higher prescription age targets remain in force. It is not a universal biological threshold.

harvest_eligibility:
  mode: minimum_stand_age
  minimum_age_years: 15
  underage_action: defer
  unknown_age_action: exclude_managed_candidate

These are validated enum values. Missing fields, misspelled fields, unsupported actions, and nonnumeric, negative, or nonfinite thresholds fail explicitly. There is no second copy of the threshold in regimes.yaml or scenarios.yaml.

Scheduling contract

  1. Resolve the prescription's existing age targets or inventory-relative offsets.
  2. Evaluate stand age at its first actual entry: inventory age + entry year − inventory year.
  3. If underage, shift the entire sequence by the smallest whole number of cycles that meets the minimum. Preserve intervals, treatment order, and higher rotation targets.
  4. Clip the result to the projection horizon. Repeated-entry end bounds remain explicit; removing the bound would allow template defaults to create unintended entries.
  5. Unknown, malformed, negative, nonfinite, or boolean age excludes managed entries. Keep grow-only, record the reason, and do not infer maturity from elapsed time alone.

Assignment records diagnostics in Prescription.notes and retains the requested prescription ID when its template becomes no_management. The scenario library emits warnings and includes audit comments in rendered keyfiles. Its cuts(name) function remains menu metadata, not stand-level eligibility.

The assignment reader accepts stand_age, STDAGE, unit_age, AGE, then STDAGE_MEAN, in that order. The first non-null field is authoritative; an invalid value is not replaced with a more convenient lower-priority age. A unit-average age does not certify every constituent patch or tree. The caller must align the age measurement with the inventory year.

Conflicting logic found

LocationFinding and disposition
Prescription assignment Fixed: offset-based entries and unknown-age fallbacks bypassed an age screen. The resolver now consumes the shared policy, accepts LETO's age alias, and rejects timing fields in params that could overwrite the checked schedule.
Scenario library Fixed: rendering accepted no age. Both build and render now accept stand_age and apply eligibility. Keyfile horizon overrides are honored; cycle lengths incompatible with the library's operation grid are rejected. Supplied regeneration is rejected if eligibility changes the harvest schedule, preventing stale establishment dates.
Executable notes Fixed: a nonempty grow-only keyfile could pass the old managed-example check. Examples now supply age and verify whether harvest keywords should be present.
Harvest allocator Caller contract: age is a priority sort, not an eligibility check. Its input must be candidates from eligible FVS trajectories. It cannot safely defer a harvest after growth and removals have already been simulated.
Raw keyword templates Low-level bypass remains: explicit years and thins lists are rendered without age context. Use assignment or the scenario library for policy-controlled runs. Raw templates remain available for FVS experiments and keyword verification.
August visualization policies Separate dated policies: heuristic industrial thinning uses age 10; BA-triggered clearcuts have no minimum age; random schedules use a 10-year re-entry lockout rather than cohort-age eligibility. The default policy passes through assignment, but random and heuristic schedules render their own event lists. They are not evidence that current production age policy is enforced. Historical results were not rewritten.
August 10 candidate builder Dated conflict: events are deduplicated by regime name, then merged onto all units of that regime. This can replace unit-specific age-adjusted dates with one representative schedule. Any reuse must retain unit-specific resolved operations.
August 17 library and August 31 batch Saved-schedule risk: August 17 resolves assignments but groups rendered runs by donor plot and prescription; August 31 consumes saved parameters. Reuse requires regenerating assignments and confirming that run keys distinguish different resolved schedules. Existing CSVs and FVS results do not gain the new policy retroactively.
Regeneration / subsequent rotations Unresolved integration: the comparison library allows only terminal regeneration harvests. The configured owner-prescription restart/repeat loop is not proven to consume regeneration metadata. A future restart must supply the new cohort's age and establishment epoch; inventory age must not continue across a clearcut. See the existing regeneration gotcha in AGENTS.md.

Verification and limits

Regression tests cover age boundaries, fractional ages, unknown ages, policy validation, unchanged rotation targets, repeated deferral, horizon clipping, timing overrides, incompatible cycles, and stale supplied regeneration. Tests exercise emitted harvest keywords, not just configuration text.

.venv/bin/python -m pytest -q
.venv/bin/python notes/check.py

Implementation verification: 77 tests passed; lint, identifier/CRS conventions and diff whitespace checks passed. The shared eligibility module has 100% statement/branch coverage. CRAP scores across it, assignment and the scenario library were all below 30 (maximum 13.3). Bounded mutation testing of the shared module in an isolated copy killed 138 of 143 mutants (96.5%); the five survivors only decorated diagnostic strings. The added boundary tests are in test_harvest_eligibility_hardening.py.

The policy pointer lives in the existing minimum-harvest-age line of AGENTS.md, keeping that file within its markdown budget. The pre-commit documentation, convention and test checks pass for this change.

Changing timing requires a new FVS run; shifting already-computed trajectory rows is invalid. No county or state simulation was rerun, so affected acreage, merchantable volume, and feasibility against TPO targets are not quantified. Minimum DBH, stand structure, harvestable area share, protected geometry, and regeneration suitability remain separate constraints. This policy does not implement the intended 25% harvestable-share screen.
