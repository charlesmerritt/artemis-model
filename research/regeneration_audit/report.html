Forest initialization & management

Forest repair
and regeneration

Impute treelists for repaired forest areas. After clearcuts, replant each stand with its original species and planting density. Keep fixed lists as a last resort.

Proposed changes14 September 2026Audit baseline: 18af1ee
01 / Policy

Three rules for choosing trees

  1. Reuse the stand's own configuration after a clearcut.

    Save species and planting density before management begins. Reuse that record for every rotation, with new seedlings after each clearcut.

  2. Impute treelists from nearby stands.

    Assign repaired raster areas treelists from the nearest suitable donor. Copy the donor tree sizes when repairing inventory for existing forest.

  3. Use a fixed fallback only when local sources fail.

    Choose a documented FIA donor list or a forest-type planting blueprint. Record why it was needed. A missing source must not silently turn an unknown stand into loblolly pine.

Riparian zones and other protected buffers remain grow-only. Their initial inventory may need repair, but they receive no harvest or planting actions.

02 / Initialization

Keep repaired acres in the weights

The audited weighting code drops unmapped pixels before calculating plot weights. A unit with partly missing coverage can therefore appear fully represented by its surviving TreeMap donors.

Count all eligible forest area first. Record mapped inventory and repaired area separately. Also record pixels with no plot match and plots with no usable trees. Impute trees for each missing contribution, then combine the contributions into the unit's treelist.

Donor selection

  1. Search direct inventory with usable live trees of the same forest type within 5 km.
  2. Search a compatible ecological group within 5 km, separating bottomland and upland hardwood.
  3. Use the applicable fixed inventory list after eligible neighbors are exhausted.

The distance limit comes from the existing policy and still needs evaluation with local data. Break equal-distance ties by stable unit ID. Exclude unusable trees before the search; imputed units must not become donor seeds within the same run.

Keep the recipient's identity, site attributes and protected status. Search once per repair patch or unit contribution to avoid repeating the same search for each pixel.

Some accepted add-back areas already contain regrown forest. Use donor treelists to represent their existing trees. Use a separate seedling rule when establishing new forest.

03 / Clearcuts

Save the planting record once

Separate protected areas and finish inventory initialization before saving the planting baseline. Save one record per unit and species with the species code, planting density in trees per acre, density source and baseline ID. This report abbreviates trees per acre as TPA. Record the input vintage and a hash of the baseline contents. All candidate trajectories and later rotations use this unchanged baseline.

1. Capture

Save the complete species and density record before any thinning or harvest.

2. Clearcut

Remove the harvested cohort. Preserve the saved record and recipient site.

3. Replant

Create seedlings from that record after the prescribed delay. Repeat at the next rotation.

Same species, same planting density

A saved record of 300 slash pine and 200 longleaf pine trees/acre produces planting requests for those same quantities after each clearcut.

Mature diameters, heights and biomass are not restored. Planting density counts trees before survival. Keep survival as a separate model parameter.

When original planting records are missing

Prefer a supplied planting record. Otherwise, use the initialized species-specific trees per acre as an INITIAL_INVENTORY_PROXY. This proxy is a proposed modeling assumption. Current stocking cannot recover trees lost to earlier mortality or thinning.

If neither record is usable, try a suitable donor baseline. Use a documented fixed blueprint if the donor search fails. Finish baseline selection before running trajectories. The clearcut renderer must fail if its baseline is missing.

Use species-specific trees per acre directly. Do not redistribute a fixed total using stand density index, discard minority species, or capture a new baseline after thinning. Preserve fractional density through FVS keyword formatting.

04 / Configuration

Define the hierarchy in config

Add one regeneration policy file. Keep donor search rules in the fallback config. Keep keyword formatting in the FVS config. These examples describe proposed interfaces; the current loaders do not implement them.

New: config/regeneration.yaml

version: 1

baseline:
  source_order:
    - original_planting_record
    - initial_inventory_proxy
    - nearest_eligible_baseline
    - fixed_planting_blueprint
  species_density: species_tpa
  capture_at: initialization_complete
  reuse: immutable_across_rotations

clearcut:
  method: replant_original
  establishment: plant
  cohort_age_at_establishment_years: 0
  missing_baseline: error

partial_harvest:
  regeneration: none

protected_units:
  management: grow_only

fallback:
  blueprint_catalog: config/fallback_treelists.yaml
  unknown_forest_type: error

Age zero is the intended cohort state at establishment. Verify its representation in the Southern FVS variant before relying on generated keywords. Thinning and selection do not trigger replanting; retention harvests need their own declared policy.

Save area contributions and planting baselines

Area contribution ledger

Key: MU_ID, component_id

Store coverage kind, eligible area, area fraction, source, donor ID, distance and fallback reason. Include unresolved area. Keep mapped inventory, repaired forest and new establishment distinct.

Saved planting baseline

Key: BASELINE_ID, SPECIES

Associate each unit with species-specific planting TPA, density source, vintage and content hash. Use the same baseline for every regime and rotation. Validate FIA control numbers and keep them as strings.

The plot-weight cutoff must not erase small repair contributions or inflate mapped coverage. If a mapped plot lacks usable live trees, return its area to the unresolved pool and search again.

06 / Acceptance

Validate replanting before the county run

  1. Baseline and repeated plantingWrite failing tests for source priority, unchanged species/TPA after thinning and two clearcuts, minority species, fractional density, invalid inputs and exact 19-digit IDs.
  2. Repair and donor selectionUse a small raster fixture containing mapped, repaired, failed-crosswalk and missing-tree cells. Account for every acre once. Test compatibility, radius boundaries, equal-distance ties, invalid nearest donors and fixed fallback last.
  3. Every renderer and callerRequire identical planting requests from both regime interfaces. Exercise the hardwood delay, repeated rotations, horizon boundaries, thinning, retention rejection and grow-only buffers.
  4. Southern FVS integrationRun mixed species through clearcut, establishment, growth and a second rotation. Check biomass removal, requested and realized stocking, species, seedling sizes, age and elapsed time. Check for unintended automatic regeneration and rounding losses.
  5. County accounting and quality checksReconcile masks, units, inputs, trajectories and outputs. Report acres by source and fallback reason. Run coverage, CRAP and mutation checks on changed modules before expanding to five counties.

Extend the existing FVS Plant renderer first. Add external restarts only if the FVS tests show that Plant records cannot produce the required cohort.

07 / Evidence

What the investigation established

The audit at 18af1ee reproduced fixed loblolly defaults, missing explicit establishment in the YAML library, a lost regeneration delay, an unconditional fixed-slot resolver, a donor retry gap and partial-coverage errors. These findings motivated this proposal.

At the time of the audit, seven characterization assertions and 26 existing tests passed. The assertions reproduced defects; the passing suite did not establish regeneration correctness. No FIA dataset or FVS binary was used in those checks.

The archived restart experiment tested a 30% proportional thinning. It did not test an age-zero replacement cohort or repeated clearcuts. The audit did not measure how many acres need fallback lists or how regeneration choices affect projected yield.
