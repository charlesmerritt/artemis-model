# Management and FVS-output test audit

Audited all 104 test functions in nine owned files, including every parametrized
branch. The local selection collected 165 test cases, plus three doctest items.
Reviewed the production functions called by these tests and the policy YAMLs.
The seams remain the existing tested functions, rendered keyfiles, SQLite reads,
CSV output, and figures. Production source files were not edited.

There are no literal `assert value == value` tests in this partition. Seventeen
test functions had circular production-derived expectations, vacuous collection
checks, or related gaps. Those now use known fixture outcomes, independent policy
literals, or complete expected collections. Four further edits clarify existing
independent checks; worked arithmetic over literal fixture inputs was not itself
a tautology.

The ownership legend comes from RDS-2025-0045 metadata, already transcribed in
`test_ownership_policy.py`. The assignment default and budget mapping are the
explicit `management_regimes.yaml` and `ownership_policy.yaml` policy. FIA query
numbers and evaluation group are the documented Florida 2022 EVALIDator contract.
S6 totals follow its hand-built three-case database and three-row owner crosswalk.

## Verification and limitations

Baseline: 164 passed, one real-data test deselected. After replacements and the
three owned doctests: 167 passed, one real-data test deselected in 9.16 seconds.

`management_rejection_probes.py` applies 12 reversible runtime faults. Every
fault raises an assertion in its replacement check, and every check passes again
after restoration. The faults cover a wrong-but-eligible default, wrong evaluation
group, invented and swapped FIA attributes, empty prescriptions and owner sets,
a changed masked sentinel, a changed sampling-weight label, empty distributions,
empty type shares, missing plot shares and a self-consistent renamed owner weight label.
Every fault survives the original committed tests and is rejected by the replacement.
These are targeted fault checks, not the repository's mutmut score.

Run the probes from the repository root. The script adds the repository to its
import path, so direct invocation needs no PYTHONPATH setting:

```sh
.venv/bin/python research/code_quality/management_rejection_probes.py
```

The production-data S6 test remains in the audit inventory but was deselected
from the offline local run. It compares two independent aggregation paths and
requires both pine and hardwood; it is a valid consistency check, not an absolute
external acreage reference. Data availability does not change its static audit.

The imputation fixture formerly titled `test_donor_ring_never_takes_a_hole_pixel_or_another_patch`
contains one connected patch, and all holes have zero donor values. Its source
filters candidate values greater than zero. The new title states its actual ring
expansion check. This audit does not claim coverage for positive donor values on
recovered pixels or for executing post-clearcut seedling establishment. The
regeneration audit records that separate source behavior.

## Per-function inventory

Each row records its disposition and the concrete assertions or exception oracle
reviewed. Literal parametrized expectations are defined in the source decorators.
`pytest.raises` checks exercise a rejectable invalid input, not an expectation
created by the same function being tested. `pytest.warns` checks preserve the
warning contract alongside independently asserted schedules.
